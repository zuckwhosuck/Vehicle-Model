================================================================================
                    JUNIGADI ANPR SYSTEM: IMPLEMENTATION GUIDE
================================================================================

This guide explains how the Automatic Number Plate Recognition (ANPR) system works, 
how to implement it on a website backend, the system requirements, and how to make 
the models self-learning over time.


--------------------------------------------------------------------------------
1. HOW THE MODELS WORK (THE PIPELINE)
--------------------------------------------------------------------------------
The ANPR system runs in two separate stages using two different AI models:

Stage 1: License Plate Detection (YOLOv8)
- Input: An image of a car/road.
- Model: YOLOv8 (`stage_5_model.pt`).
- Process: The model scans the image and outputs the exact coordinates (bounding box) 
  where the license plate is located.
- Setup: It picks the highest confidence box and crops that region from the image.

Stage 2: Character Recognition (PARSeq OCR)
- Input: The cropped plate image from Stage 1.
- Model: PARSeq (`best_parseq.ckpt`).
- Process: The crop is resized to 32x128 pixels, normalized, and read by the PARSeq model.
- Output: The actual license plate text (e.g., "GJ01AB1234") and a confidence score.

Multi-Frame Voting (Optional for Video):
- If processing video frames, the code counts how many times different texts are 
  predicted across frames and weights them by confidence. The text with the 
  highest accumulated score is selected as the final plate.


--------------------------------------------------------------------------------
2. HOW TO IMPLEMENT IT ON A WEBSITE (PRODUCTION ARCHITECTURE)
--------------------------------------------------------------------------------
Do not try to load these PyTorch models directly inside a frontend website engine 
(like Node.js or PHP). Loading the models takes time and CPU/GPU memory.

Instead, use a "Backend API Service" architecture:

1. Python API Backend (FastAPI or Flask):
   - Set up a lightweight Python web server (e.g., FastAPI) on your backend server.
   - Load the YOLO and PARSeq models once when the Python server starts.
   - Create an endpoint (e.g., `/api/predict`) that accepts uploaded images.

2. Web Frontend (The Website):
   - When a user uploads a vehicle image or a video frame, your website's 
     JavaScript (Ajax/Fetch) sends the image to the Python `/api/predict` endpoint.
   - The Python backend runs the ANPR pipeline on the image and returns a JSON 
     response containing the plate text, coordinates, and confidence.
   - The website displays the text and handles database logging.


--------------------------------------------------------------------------------
3. REQUIREMENTS (HARDWARE & SOFTWARE)
--------------------------------------------------------------------------------
Hardware Requirements:
- GPU: NVIDIA GPU with CUDA support is highly recommended for production backends. 
  It reduces processing time to under 50-100ms per image.
- CPU: A standard CPU works but is much slower (200-500ms per image), which may 
  cause delays under heavy traffic.

Software / Python Packages:
- Python 3.10 or higher.
- `torch` & `torchvision`: For deep learning operations.
- `ultralytics`: For loading and running YOLOv8.
- `strhub` (PARSeq package): For loading and running the OCR reader.
- `opencv-python` (`cv2`): For image loading, converting colors, and cropping.
- `Pillow` (`PIL`): For feeding images into PARSeq.
- `numpy`: For array calculations.
- `tqdm`: For progress bars in command-line tools.


--------------------------------------------------------------------------------
4. BLURRING THE PLATE: REDUCING FALSE BLURS (IMPORTANT RULE)
--------------------------------------------------------------------------------
To protect privacy, the system can blur the license plate in the image. However, 
YOLO can occasionally make mistakes and detect other rectangular shapes (like 
car vents, signs, or stickers) as plates.

To prevent false blurring:
- ONLY blur the bounding box if the PARSeq OCR successfully reads readable text 
  in that box.
- Use a regular expression validation check (`PLATE_REGEX`) to ensure the text 
  predicted matches standard Indian plate structures (e.g., GJ01AB1234).
- If PARSeq fails to read text, reads a low confidence score, or the text fails 
  to match the expected plate pattern, DO NOT blur the box.
- This ensures only verified license plates are blurred, keeping the rest of 
  the image intact.


--------------------------------------------------------------------------------
5. MAKING THE SYSTEM SELF-LEARNING
--------------------------------------------------------------------------------
To make your model self-learning, implement an automated feedback loop:

Step 1: Collect Data
- When the website API processes an image, log the image and its predicted text 
  into a database if:
  - The model has low confidence (meaning it is a hard example).
  - The user manually corrects a wrong prediction on the website interface.

Step 2: Admin Review (The Audit Loop)
- Build a simple admin dashboard for a human operator.
- The dashboard displays the images alongside the model's prediction and the 
  user's correction.
- The admin validates or corrects the label with a single click.

Step 3: Periodic Retraining
- Every month or after collecting enough new audited images, export these 
  new images and corrected labels.
- Run the YOLO and PARSeq training scripts using this new data to update their 
  weights.
- Swap out the old model checkpoint files (`stage_5_model.pt` and `best_parseq.ckpt`) 
  with the newly trained versions on the backend API server.

This feedback loop ensures the system continuously learns from its mistakes 
and adapts to new camera angles, lighting conditions, and license plate fonts.
